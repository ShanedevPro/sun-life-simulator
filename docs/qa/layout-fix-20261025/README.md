# 桌面画面比例修订 · 2026-10-25

版本 1.0.2。本轮只修改响应式界面；剧情、照片、选项、结局和存档格式沿用上一版。

## 问题与处理

旧规则把所有高度不超过 700px 的横向窗口都排成左右两栏。在较矮的电脑浏览器里，照片被放进左半边，字幕占据右半边大面积黑底，时间与暂停也离开了照片的边界。

现在电脑端保持居中的 9:16 竖屏画框，按窗口高度缩放，最宽 480px。时间、暂停、字幕和选项都在同一个画框里，暂停菜单也与画框对齐。较矮的电脑窗口使用紧凑排版，避免字幕或选项溢出。

手机竖屏继续铺满可用视口。窄触屏横放时保留左右阅读布局；只有粗指针、无悬停的触屏设备才使用这个适配，电脑缩短窗口不会再误触发它。较宽平板沿用居中竖屏画框。

## 验收范围

- 复现用户截图对应的 943×421 浏览器视口，并检查 844×390、500×400、1280×600、953×700、1440×900 和 1920×1080。
- 检查画框比例、居中位置、照片宽度、时间、暂停、继续按钮和暂停菜单边界。
- 检查全部 14 个选择场景的大字号排版；紧凑桌面排版曾出现文字裁切，调整留白后重新验证。
- 使用触屏浏览器上下文检查手机横放与转回竖屏，确保保持原剧情位置。
- 回归片头、剧情、结局、重选、菜单、字幕渐显、照片加载与旧进度。

本地内容检查、15 项单元测试和 32 个浏览器用例均已覆盖。生产回归中 31 项直接通过，另一项仍沿用旧桌面分栏的断言；修正为竖屏比例并单独重跑后通过，触屏横放另有独立用例覆盖。

最终测试及公开地址检查结果见 [检查记录](verification.json)。检查在桌面浏览器和模拟手机视口中完成，实体手机与真人阅读计时未执行。

公开版本与发布提交将在部署验证后补入；本地通过不能代替线上检查。
